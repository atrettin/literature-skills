# agents

The single source of truth for the three agents the skills delegate to:
`paper-ingestor`, `paper-scout`, and `terminology-prospector`. Each file holds
what every backend loads of that agent — its name, its description, and the
instructions it runs on. The body is written once; the small header that differs
between Claude Code and OpenCode is not kept here, it is generated by
`install.sh` at install time.

An agent is not installed as this file. `install.sh` reads each file and writes
a per-backend copy with the header that backend expects:

- **Claude Code** — `~/.claude/agents/<name>.md`, header `name` / `description`
  / `tools` / `model`.
- **OpenCode** — `~/.config/opencode/agents/<name>.md`, header `description` /
  `mode: subagent` / `permission` / `model`. The agent's name is the file name,
  so the header carries no `name`.

Edit a body here and re-run `install.sh` for the backend you want updated.
`git pull` does not update an already-installed agent the way a symlinked skill
does; the install regenerates it.

## The frontmatter

| Field | What it holds | Used by |
|---|---|---|
| `name` | the agent's name; must equal the file's base name. | Claude Code (OpenCode takes it from the file name). |
| `description` | what the agent does and when to start it. | both — the primary agent chooses it on this. |
| `model-tier` | `small` or `large`. Which model the install assigns it. | both — see "Models". |
| `tools` | the Claude Code tool allowlist for the agent. | Claude Code, written to its `tools` header. |
| `edit` | `allow`, `ask`, or `deny` for file writes. | OpenCode, written to its `permission.edit`. |
| `bash` | `allow`, `ask`, or `deny` for shell commands. | OpenCode, written to its `permission.bash`. |

Everything below the closing `---` is the body and is copied to both backends
verbatim. Keep it free of a line that is exactly `---`: `install.sh` finds the
body as the text after the second `---`, and the body may not re-open the
fence.

`tools` and `edit`/`bash` describe the same capability in the two backends'
different words. Claude Code grants an explicit tool list; OpenCode gates a
few categories and leaves the rest at their defaults. A reader that only greps
needs `read`, `glob`, `grep`, which neither backend lists because both allow
them by default.

## Models

`install.sh` maps a `model-tier` to a model name and writes it into the header.
The names come from the command line: `--small MODEL` for the small tier and
`--large MODEL` for the large tier. When a tier has no name, the backend falls
back to its own default:

| Backend | No name given for the tier |
|---|---|
| Claude Code | `haiku` for small, `sonnet` for large — always written. |
| OpenCode | no `model` line, so the subagent inherits the model of the agent that invoked it. |

The current tiers: `paper-scout` is `small`; `paper-ingestor` and
`terminology-prospector` are `large`. Why one is small and the other two are
large is in [TUNING.md](../TUNING.md), under "Choosing a model for an agent".

## Adding an agent

Add `agents/<name>.md` with the frontmatter above and its body, then add the
name to the `agents` list in `install.sh`. The name must be one the skills may
start, so name it the way a skill will refer to it.
